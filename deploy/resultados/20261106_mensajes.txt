1. LO QUE SE ENCONTRO
-------------------------------------------------------------
La auditoria de los 47 raise_application_error de los packages encontro tres
problemas reales y varios de forma:

a) Errores de negocio reetiquetados. Seis manejadores WHEN OTHERS se tragaban
   el codigo/mensaje original:

     FACTURADO -> CANCELADO (trigger -20070) con la app daba:
       Error en pkg_presupuestos.prc_cancelar_presupuesto: ORA-20070: ...
     cancelar una factura (trigger) daba:
       Error en pkg_facturacion.prc_anular_factura: ORA-20070: ...
     borrar una linea de una factura PAGADA daba:
       ORA-20002: ORA-20002: No se pueden eliminar lineas ...   (duplicado)

   El usuario perdia el motivo y veia el nombre del package.

b) Los triggers de transiciones terminaban con:
     «Si es una correccion, hazlo con CLIENT_INFO = SYPEX_FORZAR_ESTADO.»
   Es una escotilla de operacion, no algo que se le diga a quien factura.

c) Los errores inesperados mostraban «No se pudo guardar la linea: ORA-06502:
   ...» : util para el tecnico, ruido para el usuario.

2. LO QUE SE CAMBIO
-------------------------------------------------------------
- En 4 bodies (pkg_facturacion, pkg_presupuestos, pkg_presupuesto_detalle,
  pkg_factura_detalle), 8 manejadores ahora:
     if sqlcode between -20999 and -20000 then raise; end if;
     prc_log_error(... p_detalle => SQLERRM, p_sentencia => backtrace);
     raise_application_error(-20xxx, '<mensaje limpio>. Avisa al administrador.');
  Es decir: el error de negocio llega intacto y el inesperado deja el detalle
  en SYN_ERROR_LOG (el monitoreo del 2026-11-06) con un mensaje presentable.
- Los dos triggers de estados: el mensaje explica la regla y ya no menciona
  CLIENT_INFO. La escotilla sigue funcionando (se probo).

3. ANTES Y DESPUES (medido)
-------------------------------------------------------------
  presupuesto FACTURADO -> cancelar:
    antes: Error en pkg_presupuestos.prc_cancelar_presupuesto: ORA-20070: ...
    ahora: No se puede pasar un presupuesto de FACTURADO a CANCELADO. Un
           presupuesto CANCELADO ya no se mueve, y uno FACTURADO solo vuelve a
           APROBADO (anulando la factura).

  factura PAGADA -> borrar linea:
    antes: ORA-20002: ORA-20002: No se pueden eliminar lineas ...
    ahora: No se pueden eliminar lineas de una factura en estado PAGADA: es un
           documento cerrado.
